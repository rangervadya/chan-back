# Camelion

Camelion — приложение на Flutter для изменения цвета выбранного объекта на фотографии с сохранением его формы и фактуры. Для обработки изображений приложение обращается к серверному API.

> **Статус установки:** инструкции ниже описывают сборку и распространение приложения. Чтобы установить готовую версию обычным пользователям, сначала нужно собрать Android APK и/или загрузить iOS-сборку в TestFlight. Наличие исходников на GitHub само по себе не устанавливает приложение на телефон.

## Что понадобится

- Flutter SDK и Git для сборки клиентского приложения.
- Android Studio и Android SDK — для сборки и установки на Android.
- Mac с Xcode — для сборки и установки на физический iPhone.
- Доступный сервер Camelion API. Клиент не сможет выполнять обработку изображений, если сервер выключен или недоступен.

Команды Flutter необходимо выполнять **в каталоге, где находится `pubspec.yaml`**. Если приложение лежит в `client/`, сначала перейдите туда:

```bash
cd client
```

Если `pubspec.yaml` расположен в корневой папке репозитория, выполняйте команды оттуда.

## Настройка сервера

Перед использованием телефона убедитесь, что серверный API запущен и доступен с устройства. Адрес `SERVER_URL` должен указывать на базовый адрес API, который ожидает клиент.

Для локальной разработки проверьте серверные инструкции и конфигурацию Docker Compose в каталоге проекта, где находится `docker-compose.yml`.

**Для реального распространения приложения используйте HTTPS**, например `https://api.example.com`, а не HTTP. Не публикуйте в GitHub `.env`, API-ключи, токены Cloudflare, пароли или другие секреты.

## Запуск приложения для разработки

1. Установите Flutter SDK и проверьте окружение:

   ```bash
   flutter doctor
   ```

2. Перейдите в каталог с `pubspec.yaml` и скачайте зависимости:

   ```bash
   flutter pub get
   ```

3. Подключите разблокированный телефон по USB либо запустите эмулятор и проверьте, что Flutter его видит:

   ```bash
   flutter devices
   ```

4. Запустите приложение, передав адрес сервера и API-ключ, которые вы получили для разработки:

   ```bash
   flutter run \
     --dart-define=SERVER_URL=https://YOUR_SERVER_DOMAIN \
     --dart-define=API_KEY=YOUR_DEVELOPMENT_API_KEY
   ```

Замените `https://YOUR_SERVER_DOMAIN` и `YOUR_DEVELOPMENT_API_KEY` на реальные значения. Не добавляйте настоящий ключ в этот README или в коммиты Git.

## Установка на Android

### Вариант A: собрать APK для тестирования

1. На компьютере установите Flutter SDK и Android SDK.
2. Перейдите в каталог Flutter-проекта — в папку с `pubspec.yaml`.
3. Соберите APK, указав доступный сервер и конфигурацию для сборки:

   ```bash
   flutter pub get
   flutter build apk --release \
     --dart-define=SERVER_URL=https://YOUR_SERVER_DOMAIN \
     --dart-define=API_KEY=YOUR_DEVELOPMENT_API_KEY
   ```

   Для первой внутренней проверки можно собрать debug APK командой `flutter build apk --debug`.

4. APK обычно появится здесь:

   ```text
   build/app/outputs/flutter-apk/app-release.apk
   ```

   Для debug-сборки имя файла обычно заканчивается на `app-debug.apk`.

5. Передайте APK на Android-телефон защищённым способом, откройте файл и подтвердите установку. Android может попросить разрешить установку приложений из используемого источника, например браузера или файлового менеджера. Разрешайте её только для файла, которому доверяете.

6. Откройте Camelion и проверьте соединение с сервером.

### Вариант B: установить через USB во время разработки

Включите на Android «Для разработчиков» и «Отладку по USB», подключите телефон к компьютеру и выполните в каталоге Flutter-проекта:

```bash
flutter devices
flutter run \
  --dart-define=SERVER_URL=https://YOUR_SERVER_DOMAIN \
  --dart-define=API_KEY=YOUR_DEVELOPMENT_API_KEY
```

### Перед распространением APK

Для постоянного распространения настройте **релизную подпись Android** и безопасное хранение ключа подписи. Не публикуйте файл keystore или его пароли в GitHub. Для публикации в Google Play обычно создают подписанный Android App Bundle:

```bash
flutter build appbundle --release \
  --dart-define=SERVER_URL=https://YOUR_SERVER_DOMAIN \
  --dart-define=API_KEY=YOUR_DEVELOPMENT_API_KEY
```

Подробности — в [официальной инструкции Flutter для Android](https://docs.flutter.dev/deployment/android).

## Установка на iPhone

На iPhone нельзя установить обычный Android APK. Для сборки iOS-приложения необходим Mac с Xcode. Самый удобный способ раздать тестовую версию нескольким людям — **TestFlight**.

### Вариант A: запуск на своём iPhone для разработки

1. Установите Xcode на Mac и откройте его хотя бы один раз, чтобы завершить первичную настройку.
2. Подключите iPhone кабелем, разблокируйте его и подтвердите доверие компьютеру.
3. В Xcode откройте `ios/Runner.xcworkspace` внутри Flutter-проекта.
4. В настройках цели `Runner` выберите уникальный Bundle Identifier и настройте Signing Team. Для распространения тестовой сборки могут понадобиться учётная запись Apple Developer и подходящая подпись.
5. Вернитесь в каталог с `pubspec.yaml` и выполните:

   ```bash
   flutter pub get
   flutter devices
   flutter run \
     --dart-define=SERVER_URL=https://YOUR_SERVER_DOMAIN \
     --dart-define=API_KEY=YOUR_DEVELOPMENT_API_KEY
   ```

### Вариант B: раздать приложение через TestFlight

1. Настройте подпись iOS-приложения и Bundle Identifier в Xcode.
2. Подготовьте конфигурацию сервера для сборки и создайте IPA:

   ```bash
   flutter build ipa --release \
     --dart-define=SERVER_URL=https://YOUR_SERVER_DOMAIN \
     --dart-define=API_KEY=YOUR_DEVELOPMENT_API_KEY
   ```

3. Загрузите созданную сборку в App Store Connect. Для распространения через TestFlight потребуется настроить приложение в App Store Connect и выполнить требования Apple для тестирования.
4. В App Store Connect откройте раздел TestFlight и пригласите тестировщиков по email или доступной ссылке.
5. На iPhone тестировщик устанавливает приложение **TestFlight** из App Store, открывает приглашение и устанавливает Camelion через TestFlight.

Пользователю не нужно скачивать исходники из GitHub. Ему нужна ссылка-приглашение TestFlight или ссылка на опубликованное приложение.

Официальные инструкции: [сборка и публикация iOS-приложения Flutter](https://docs.flutter.dev/deployment/ios) и [TestFlight от Apple](https://developer.apple.com/testflight/).

## Переменные конфигурации

| Переменная | Назначение |
|---|---|
| `SERVER_URL` | Базовый адрес серверного API Camelion. Для публичного использования предпочтителен HTTPS. |
| `API_KEY` | Ключ, который клиент передаёт серверу, если серверная конфигурация его требует. Получайте его у администратора сервера и не размещайте в репозитории. |

Значения, переданные через `--dart-define`, попадают в собранное приложение. **Не считайте ключ, встроенный в мобильное приложение, секретным:** его можно извлечь из сборки. Для публичного продукта предпочтительно использовать полноценную авторизацию пользователей, ограничения частоты запросов и серверную проверку прав, а не общий секретный ключ, встроенный во все копии приложения.

## Решение проблем

### Приложение сообщает об ошибке API key

- Проверьте, что при сборке или запуске передан правильный `API_KEY`.
- Убедитесь, что ключ совпадает с настройками сервера.
- Не публикуйте ключ в логах, скриншотах, README или GitHub Issues.

### Сервер недоступен

- Проверьте, что API и контейнер сервера запущены.
- Убедитесь, что телефон может открыть серверный адрес через свою сеть.
- Проверьте правильность `SERVER_URL`, порт, правила firewall и обратный прокси.
- Для публичного использования настройте HTTPS; HTTP-соединения могут блокироваться системными настройками безопасности устройства и не защищают передаваемые данные.

### APK установлен, но перекрашивание не работает

Установка приложения не гарантирует доступность backend. Проверьте серверные логи и то, что используемая сборка содержит правильный адрес API.

### На iPhone не удаётся установить сборку

Проверьте Bundle Identifier, подпись приложения, выбранную команду Signing Team и настройки Xcode. Для распространения нескольким тестировщикам предпочтительнее TestFlight, а не пересылка IPA-файла напрямую.
